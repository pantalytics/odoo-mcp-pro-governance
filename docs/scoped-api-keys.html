MCP Pro · Governance

One user, many scoped API keys.

Today every API key inherits the full rights of the user it belongs to. Tomorrow each key carries only the role it needs — so an enrichment bot cannot read invoices, and a finance bot cannot edit contacts.

Before

The API key is as powerful as the user.

The problem. Every API key inherits the full access of the user. To let an automation tool only enrich contacts, you either accept the full data risk — or pay for an extra user with a stripped-down role.

After

The API key carries its own role.

Give the key only the access it needs. The API key picks one role from the user's set of roles. The key's scope can be smaller than the user's. Powered by Role Based Access Control (OCA).

* App can be anything that calls Odoo over the API — an AI chat (Claude, ChatGPT), an automation tool (n8n), an AI agent (OpenHands) or a plain cron job.
